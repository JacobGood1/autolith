* Presentation boundaries

There is no central marker requirement in =application-present= or the
finalized-ledger append function.

- =src/application/runtime.lisp:2477–2490= wraps the first pending slash-command
  response as =› <command>= followed by =└ …=.
- =src/application/runtime.lisp:2529–2530= clears that pending wrapper after the
  first emission.
- =src/application/operation.lisp:941–950= disables the pending wrapper for
  native Lisp command invocation.
- =src/terminal/responsive-input.lisp:3923–3947= executes the slash command before
  presenting the canonical command hint. The first-response wrapper is normally
  consumed before that hint.
- =src/application/runtime.lisp:2049–2080= preserves explicit transcript headers.
- =src/terminal/ui.lisp:2705= does not add a marker at the finalized sink.
- Exit resume instructions are separate, unmarked epilogue output at
  =src/startup/main.lisp:319=.

The audit involved no code changes or test runs. No symbols were selected.

* Standalone notice style

Automatic permission decisions, idle compaction, update notices, recovered-input
startup notices, input-storage warnings, and prompt-submission errors use =·=
followed by a lowercase start. For example:

: · compacting idle history before estimated cache expiry

Command replies, canonical command hints, and local Lisp evaluation output are
outside this change.
